## Comparison dimensions

Implementation/Midnight depth: inspect contract source, generated artifacts and reproducible network evidence; repository presence alone is insufficient. Privacy: inspect witness disclosures, signer/holder binding, identifier scope, public reads, metadata and issuer knowledge. Lifecycle: reproduce expiry, current revocation, stale receipts and authorization races. Security: require negative tests, threat boundaries and key governance. UX: exercise real pending/failure states. SDK: require a reference application using the actual verifier. Adoption: distinguish operator claims, developer demos and external testers. Performance: compare only measured equivalent execution modes.

## VeilPass position

The intended combination is reusable developer qualifications, precise application policies, a complete current-validity lifecycle and a small SDK without a universal holder identifier. These ideas are not claimed unique. The delivered V2 addition currently demonstrates two policy/audience domains, monotonic revocation, trusted-time circuit constraints, durable verifier challenge consumption, explicit execution modes and reference applications.

Current gaps prevent a defensible “best credential platform” claim: two-record issuer-known bearer batch, no VC signature integration, no holder-owned keys, no V2 finalized adapter or fresh deployed proof evidence, no external pilot, no scalable issuer registry, and no general policy builder. Prioritize closing those gaps over adding visual complexity. Competitor strengths in role isolation, runbooks and operational evidence are useful standards to meet.
